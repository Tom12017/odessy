## 源码与发布基线

当前 Windows x64 候选版本基于 `fix/windows-setup-long-paths` 分支的 `1834c1a441fb444ecb1712429c550bafce7d3b19`，加上相邻 `verification.json` 中记录的未提交 Piper/安装修复。这是已记录的含未提交改动的源码快照，不能仅用 `1834c1a` 代表全部打包修复。

维护者于 2026 年 11 月 18 日确认重新构建的 EXE 安装成功。[候选版本回执](../verification/windows-piper-installer-2026-11-18.md)（English only）记录校验值、109 项相关 Python 测试、650 项 Flutter 测试通过/15 项跳过、静态分析无问题，以及隔离安装后的 Piper 合成和剩余限制。完整 Python 测试在结束前被停止，不能宣称全部通过。

`ssh -G failed` 来自验证启动脚本漏传 Windows `ProgramData` 环境变量。修正启动环境后，同一已安装应用的认证 SSH 检查通过，维护者确认登录成功。本次修复没有替换应用文件或安装包。新增七项回归用例覆盖系统/用户目录变量保留；52 项 Windows 启动、已安装服务及 SSH 检查通过。

公开预览标签仍为 **v0.5.0-alpha**。本次文档更新没有上传、签名或发布安装包。已测试的分发候选版本与公开下载仍需区分。现有手册图片及[较早安装回执](../verification/ssh-voice-installed-update-2026-11-18.md)（English only）保留各自旧源码标识，不能自动验证当前候选版本。

## 首次贡献者运行

常规的已安装使用流程是：**open app → Settings → model/workspace → chat**（打开应用 → 设置 → 模型/工作区 → 对话）。桌面端会启动自身经过认证的服务，无需用户自行操作后端终端。[源码方式安装](./getting-started.md)在安装开发用 SDK 后使用同一套受管生命周期。CLI 假模型与手工令牌握手属于独立的组件/API 检查，不是产品的主要上手途径。

[GitHub issue 列表](https://github.com/Trisoma/odessy/issues)与[领域归属路径](./CONTRIBUTING.md#通往领域负责人的路径)提供了具体的贡献途径。它们不能证明外部贡献者能够成功上手，也不能证明维护者的响应时间或会授予贡献者权限。首次运行的耗时情况，以及外部读者对 golden path 的验收情况，仍未测量。

## 能力矩阵

| 能力 | 已实现范围 | 重要边界 |
| --- | --- | --- |
| Desktop（桌面端） | 生产可用的 Flutter 外壳、项目/最近对话、inspector（检查器）、Activity & usage（活动与用量）、Jobs（作业）、Handoffs（交接）以及八个设置分组 | 页面可见并不能保证其后端能力可用。 |
| Durable history（持久历史） | 保存在用户配置文件本地的 SQLite 项目/对话/事件、搜索与有界导出 | 浏览历史没有副作用；已存储的调用不会被重放。 |
| Custom continuation（Custom 续接） | 将已完成的公开对话轮次恢复到全新的已授权控制器中 | 工作区绑定必须一致；授权（grants）、审批、作业与进程句柄都不会被恢复。 |
| Harness | 可选择的运行时，以及可读的已保存历史 | 重启后继续，以及 Custom 访问模式/上下文的对等能力均不可用；不会静默回退。 |
| Access modes（访问模式） | Custom 的 ask/auto/full（询问/自动/完全）模式，带服务确认与版本修订 | 现有策略、硬性拒绝、敏感路径与独立授权仍然有效。 |
| Context/memory/retrieval（上下文/记忆/检索） | 显式的项目事实、需主动开启（opt-in）的有界词法索引，以及 Custom 的上下文/引用 | 仍需要来源校验与当前实时工作区的权限。不会进行自动云端索引。 |
| Interactive terminal（交互式终端） | 本地 Windows PTY，配有经验证的打包 Node/原生辅助程序（native helper）与显式授权 | 以用户的操作系统权限运行；不提供远程 PTY、句柄恢复或输入重放。缺少闭环即视为不可用。 |
| Checkpoints（检查点） | 基于 Git 的有界文本快照与预览；受支持的非 Windows 恢复使用精确审批与安全快照 | 在基于句柄的安全机制就绪前，Windows 恢复已在服务与 UI 中禁用。创建/列出/预览仍可用；二进制/敏感/不受支持的文件被排除。 |
| Monitoring（监控） | 可选的 Go 聚合组件，支持本地/配对遥测与只读 SSH 状态 | 连通性、权限与数据新鲜度仍需分别判断。监控 DTO 不授予执行或工作区访问权限。 |
| SSH execution（SSH 执行） | 显式选择临时的 Custom 目标，并执行逐条精确批准的 `ssh.run` 命令 | 与监控相互独立；不提供远程沙箱、PTY、文件检查器，也不支持 Harness 通过 SSH 执行。服务重启后需重新连接。 |
| Voice（语音） | CPU 推荐 Piper，可选 Kokoro；Whisper 输入与唤醒下载分别选择 | 已验证安装后的 Piper 模型加载/合成；麦克风、播放、回声和唤醒需按设备验收。 |
| Setup（安装设置） | Windows 安装程序、私有运行时、带版本维护及可选 Piper/Kokoro 安装 | 维护者已确认此候选版本安装成功；签名、广泛硬件及干净机器验收仍需分别完成。 |

## 平台矩阵

| 平台 | 证据与支持级别 |
| --- | --- |
| Windows x64 | 主要的开发者预览目标平台；针对特定快照存在源码/CI 与已记录的原生/已安装检查。最终候选版本的验收仍另行进行。 |
| Linux x86_64 | 有源码/CI 覆盖；最终快照的可移植打包与原生 GUI 验收尚未确立。 |
| Jetson/Linux ARM64 | 仅有针对特定方向的历史监控、配对与语音证据。并不构成对桌面端或执行能力的普遍性声明。 |
| macOS | 未经验收。 |

本页不主张提供通用的最低 RAM/GPU 规格、完整沙箱、自主协调（autonomous coordination）对等能力或 MCU 支持。SSH 命令执行仅限于上文所述的有界 Custom 范围；它既不是通用的远程 IDE，也不构成隔离保证。

## beta 声明之前的门槛

1. 在基于句柄的保护机制经验证之前，发布候选版本中的 Windows 检查点恢复应保持禁用。对其他任何安全性/数据丢失方面的发现，要么予以解决，要么禁用相关功能。
2. 基于最终源码快照构建并审计一个一致的候选版本，固定运行时/辅助程序闭环、许可证与构建产物哈希。
3. 针对该候选版本验证隔离环境下的安装/更新/卸载，以及配置文件/历史/设置的保留情况；区分夹具（fixtures）与真实的保险库（vault）/提供商证据。
4. 使上手引导、受支持的工作流、截图与限制说明与该候选版本保持一致。
5. 记录维护者的视觉验收结果，以及其余平台/硬件/提供商门槛。

Alpha 并不豁免安全要求。不得将不安全的恢复路径当作生产环境安全的能力分发。参见[发布验证](../release-verification.md)（English only）。
